# Публикация сайта

Сайт статический, поэтому подходит любой хостинг, умеющий отдавать файлы.
Ниже — бесплатные варианты и что у них с доменом.

## Коротко

| Вариант | Бесплатный адрес | Свой домен | Плюсы | Минусы |
|---|---|---|---|---|
| **GitHub Pages** (рекомендую) | `login.github.io` | да, бесплатно + HTTPS | бесплатно навсегда, версии в git, обновление = `git push` | нужен GitHub-аккаунт и git |
| **Netlify** (Drop) | `имя.netlify.app` | да, бесплатно + HTTPS | публикация перетаскиванием папки, без git | лимиты на трафик, зарубежный сервис |
| **Cloudflare Pages** | `имя.pages.dev` | да, бесплатно + HTTPS | самый быстрый CDN | из России Cloudflare временами тормозит — для клиентов из РФ рискованно |
| **Beget FreeHosting** | технический поддомен `*.bget.ru` | да | всё в РФ, обычный FTP, без карты | 1 ГБ, 1 сайт, техподдержки на тарифе нет |

Бесплатных **настоящих** доменов сейчас практически нет: Freenom (`.tk`, `.ml`, `.ga`)
раздачу прекратил. Так что «бесплатный домен» = поддомен хостинга из таблицы.
Когда захочется солидный адрес: `.ru` — примерно 200–400 ₽/год (физлицу нужны паспортные
данные), `.com` — 1000–1500 ₽/год. Домен покупается отдельно у регистратора
(reg.ru, beget, timeweb) и бесплатно привязывается к любому из хостингов выше.

Разумный путь: запуститься на бесплатном поддомене, показать сайт Марии, а когда
контент устоится — купить `krugovova.ru` и переключить домен. Ломать при этом ничего
не придётся, адрес сайта меняется в одном месте.

## GitHub Pages — по шагам

```bash
cd /home/dmikhin/vibe/www
git init -b main
git add .
git commit -m "Сайт-визитка: скелет"
```

1. Создать пустой репозиторий на github.com, например `krugovova-site` (публичный —
   Pages на приватных репозиториях требует платный план).
2. Привязать и отправить:

   ```bash
   git remote add origin git@github.com:USER/krugovova-site.git
   git push -u origin main
   ```

3. В репозитории: **Settings → Pages → Source: Deploy from a branch → main / (root)**.
4. Через 1–2 минуты сайт открывается по адресу `https://USER.github.io/krugovova-site/`.

Дальше каждое обновление — обычный `git push`.

Если хочется адрес вида `https://USER.github.io/` без хвоста — репозиторий нужно
назвать ровно `USER.github.io`.

### Свой домен потом

1. Купить домен у регистратора.
2. В DNS домена добавить записи:
   - `A` для `@` → `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`
   - `CNAME` для `www` → `USER.github.io`
3. В **Settings → Pages → Custom domain** вписать домен и включить **Enforce HTTPS**
   (сертификат Let's Encrypt выпустится сам, обычно за 10–30 минут).
4. Заменить `example.com` в `robots.txt`, `sitemap.xml` и в `<link rel="canonical">` в
   `index.html` на реальный домен.

## Netlify — если не хочется возиться с git

Открыть <https://app.netlify.com/drop> и перетащить туда папку `www`.
Сайт публикуется сразу, адрес вида `random-name.netlify.app` меняется в настройках.
Обновление — перетащить папку заново. Свой домен и HTTPS подключаются бесплатно
в **Domain settings**.

## Beget FreeHosting — если хочется, чтобы всё было в России

Регистрация на <https://beget.com/ru/hosting/free>, затем залить файлы по FTP в папку
`public_html` сайта. Даётся 1 ГБ, один сайт, техподдержка на этом тарифе не оказывается.

## Что не забыть после публикации

- Заменить `example.com` на реальный адрес в `robots.txt`, `sitemap.xml`, `canonical`.
- Подключить форму (см. `README.md`) — либо убрать её и оставить только Telegram и почту.
- **Про 152-ФЗ**: если форма отправляет данные в зарубежный сервис (Formspree и подобные),
  формально это трансграничная передача персональных данных. Для маленькой частной
  практики самый спокойный вариант — вообще не собирать данные на сайте, а вести запись
  через Telegram и почту; тогда форму можно удалить, а `privacy.html` сократить.
- Аналитика — Яндекс.Метрика: счётчик вставляется перед `</body>` в `index.html`.
  Если счётчик подключён, cookie-уведомление в разметке оставить.
- Проверить сайт на телефоне и прогнать через PageSpeed Insights.
