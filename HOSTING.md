# Где разместить статический сайт

Обзор бесплатных вариантов под этот проект. Проверено 30 августа 2026 —
цены и условия меняются, ссылки на первоисточники внизу.

## Сводка

| Сервис | Бесплатный адрес | HTTPS | Свой домен | Как обновляется |
|---|---|---|---|---|
| **GitHub Pages** | `user.github.io` | да | **да**, бесплатно + Let's Encrypt | `git push` |
| **GitLab.com Pages** | `namespace.gitlab.io` | да | **да**, на тарифе Free, + Let's Encrypt | `git push` + CI-джоба |

## Подробности

### GitHub Pages

Самый предсказуемый вариант. Свой домен и сертификат — бесплатно.
DNS для корня домена (IP проверены):

```
@   A   185.199.108.153
@   A   185.199.109.153
@   A   185.199.110.153
@   A   185.199.111.153
www CNAME  ВАШ-ЛОГИН.github.io.
```

Дальше `Settings → Pages → Custom domain`, подождать выпуска сертификата и включить
`Enforce HTTPS`. Репозиторий должен быть публичным (на бесплатном тарифе GitHub).
Пошагово — в `DEPLOY.md`.

### GitLab.com Pages

Единственная альтернатива GitHub, где свой домен точно работает на бесплатном тарифе.
Отличия: публикация идёт через CI-джобу `pages` в `.gitlab-ci.yml`, и **домен нужно
подтвердить TXT-записью** — неподтверждённые удаляются через 7 дней.
Корень домена — A-запись `35.185.44.232` (AAAA `2600:1901:0:7b8a::`),
поддомен — CNAME на `namespace.gitlab.io`.

### SourceCraft Sites (Яндекс)

Запущен в феврале 2025. Бесплатно, HTTPS из коробки, свой TLS-сертификат грузить не надо.
Публикуется из `.sourcecraft/sites.yaml` через их CI.

Ограничение, которое решает всё: **публиковать можно только из публичного репозитория
публичной организации**. Свой домен в документации не упоминается.

### GitVerse Pages (СберТех)

Бесплатно на тарифе Free, HTTPS. Адрес `<owner>.gitverse.site`, для проекта —
`<owner>.gitverse.site/<repo>`. Ограничения: артефакт сборки до 500 МБ, один сайт на
аккаунт и по одному на репозиторий, все пути в разметке должны быть относительными.
Про свой домен в документации ничего — их же документация советует спрашивать поддержку.

### GitFlic

Функции публикации статики нет. В документации есть CI/CD, реестр пакетов, REST API,
self-hosted — раздела про Pages нет. Максимум: собрать сайт в их CI и залить на
сторонний хостинг, то есть то же, что мы делаем скриптом на Beget.

### Beget FreeHosting — где сайт лежит сейчас

<http://<ваш-логин>.beget.tech/> — рабочий макет. Плюсы: всё в РФ, обычный FTPS, без карты.
Минусы: 1 ГБ, один сайт, техподдержки на тарифе нет и **HTTPS отсутствует** — на узле
`m2.free5.beget.com` порт 443 закрыт. Грабли и команда выкладки — в `README.md`.

## Со своим доменом, но за деньги

Если хочется, чтобы всё было в российской юрисдикции и при этом со своим доменом и
сертификатом, — объектные хранилища с режимом статического сайта:
Yandex Cloud Object Storage (плюс их Certificate Manager), Selectel, VK Cloud.
Не бесплатно, но для визитки это единицы рублей в месяц.

## Что выбрать здесь

- **Нужен `krugovova.ru`** → GitHub Pages или GitLab Pages. У российских Pages-сервисов
  свой домен не заявлен.
- **Домен пока не нужен, но хочется HTTPS** → SourceCraft Sites или GitVerse Pages:
  по этому пункту они строго лучше бесплатного Beget.
- **Мария правит тексты сама** → ничего из списка не подходит: везде обновление через
  `git push`. Это путь для статики, см. `TILDA.md` для основного плана.
