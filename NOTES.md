## Домен и HTTPS (GitHub Pages + reg.ru)

### Как устроено сейчас

Домен `krugovova.ru` куплен на reg.ru, DNS там же (`ns1/ns2.reg.ru`), сайт — GitHub Pages
из ветки `main`. Зона:

```
@    A      185.199.108.153 / .109.153 / .110.153 / .111.153
@    AAAA   2606:50c0:8000::153 / :8001::153 / :8002::153 / :8003::153
www  CNAME  dmitry-j-mikhin.github.io.
```

Файл `CNAME` в корне репозитория — одна строка `krugovova.ru`. **Удалять нельзя:**
без него GitHub перестаёт обслуживать домен.

### Выпуск сертификата: чего ожидать

- **Ждать можно до суток.** GitHub пишет это прямым текстом на странице настроек
  репозитория, под чекбоксом «Enforce HTTPS»: *«Please allow 24 hours for this process
  to complete»*. Фраза «up to 15 minutes» в рамке выше — дежурный оптимизм.
- **Прогресс виден только в вебе.** На странице настроек есть шкала «1 of 3» и подпись
  вроде «Certificate Requested: Authorization created». API отдаёт только состояние:
  ```bash
  gh api repos/dmitry-j-mikhin/krugovova-site/pages --jq '.https_certificate'
  ```
- **`https_certificate: null` — это не «идёт выпуск», это «заявки нет вообще».**
  Если поле пустое больше часа, выпуск не начинался. Состояние `authorization_created`
  уже означает, что заявка создана и Let's Encrypt проверяет домен.

### Если выпуск не начинается

Штатный способ пересоздать заявку — снять домен и поставить обратно:

```bash
gh api --method PUT repos/dmitry-j-mikhin/krugovova-site/pages \
  -H "Content-Type: application/json" --input - <<< '{"cname": null}'
gh api --method PUT repos/dmitry-j-mikhin/krugovova-site/pages \
  -H "Content-Type: application/json" --input - <<< '{"cname": "krugovova.ru"}'
git pull --ff-only origin main    # GitHub сам сделает коммиты Delete CNAME / Create CNAME
```

На минуту-две сайт уйдёт в 404. **Больше одного-двух раз так делать нельзя:**
у Let's Encrypt лимит — 5 одинаковых сертификатов на набор имён в неделю, упрёшься
и будешь ждать до конца недели.

### Что проверять, если застряло

Всё это проверяли — ни одна из причин не подтвердилась, но список рабочий:

```bash
dig +short @ns1.reg.ru krugovova.ru CAA      # пусто = выпускать разрешено любому УЦ
dig +short @8.8.8.8 krugovova.ru DS          # пусто = DNSSEC не мешает
curl -sI http://krugovova.ru/.well-known/acme-challenge/probe   # 404 без редиректа — норма
curl -sI http://www.krugovova.ru/.well-known/acme-challenge/probe
gh api repos/dmitry-j-mikhin/krugovova-site/pages/builds/latest --jq '{status,error:.error.message}'
```

### Заблуждения, которые стоили времени

- **Пуши в `main` выпуску не мешают.** Была гипотеза, что пересборки Pages перебивают
  очередь выпуска — неверна. Проверено: во время сборки состояние заявки не сбрасывалось,
  а ожидание без единого пуша ничего не ускорило.
- **`github.com/settings/pages` — не та страница.** Это настройки аккаунта, раздел
  «Verified domains» (защита от чужой публикации на вашем домене). К сертификату
  отношения не имеет, пустой список там ни на что не влияет. Нужна страница
  репозитория: `github.com/dmitry-j-mikhin/krugovova-site/settings/pages`.

### Продление

- **Сертификат — сам.** Let's Encrypt на 90 дней, GitHub перевыпускает заранее.
  Ломается только если сломать DNS или удалить `CNAME`. Причём заметно это станет
  не сразу: текущий сертификат доживёт срок, а потом при включённом `Enforce HTTPS`
  сайт станет недоступен совсем.
- **Домен — руками.** `krugovova.ru` оплачен до **8 сентября 2027**. Стоит включить
  автопродление в личном кабинете reg.ru.

### reg.ru: мелочи панели

- **CNAME на `www` не создаётся, пока там висит A-запись.** Сначала удалить A, потом
  добавить CNAME — обратный порядок упирается в ошибку.
- Отдельной кнопки «применить» нет, панель пишет «Внесены изменения зоны» сразу.
- Список записей сдвигается после каждой операции — легко промахнуться мимо строки.
  Перезагружать страницу после каждого шага.
- **Изменения доезжают не мгновенно.** Один раз снимок зоны застал промежуточное
  состояние, и показалось, что часть правок не сохранилась. Серийник SOA сменился
  примерно через три минуты. Проверять по `dig +short @ns1.reg.ru krugovova.ru SOA`.

### Jekyll

GitHub Pages собирает сайт Jekyll'ом, и он **пропускает файлы и папки с подчёркиванием**.
Поэтому `_og.html` (сборщик картинки превью) лежит в репозитории, но не публикуется —
проверено, отдаёт 404. Если когда-нибудь появится `.nojekyll`, файл станет публичным.

## Проверка вёрстки headless-браузером

Скриншоты снимаются так:

```bash
python3 -m http.server 8765 &
chromium-browser --headless --disable-gpu --no-sandbox --hide-scrollbars \
  --window-size=1440,4000 --virtual-time-budget=10000 --screenshot=out.png http://127.0.0.1:8765/
```

Грабли, каждая стоила ложного вывода:

- **У headless Chromium минимальная ширина окна ~500px.** `--window-size=400` даёт
  картинку шириной 400, но вёрстку считает в 500 — контент выглядит обрезанным справа,
  и кажется, что страница переполняется по горизонтали. Это артефакт, а не баг вёрстки.
  **Узкие экраны проверять через iframe** нужной ширины внутри более широкой страницы:

  ```html
  <iframe src="/" style="width:360px;height:844px;border:0"></iframe>
  ```

- **Маленькая высота окна тоже ломает снимок.** `--window-size=1440,120` рисует мусор;
  ставить от 400 и обрезать потом.
- **`--dump-dom` игнорирует `--window-size`** — всегда считает вёрстку в 485px.
  Чтобы измерить что-то из JS, надо не дампить DOM, а **рисовать результат прямо
  на странице** (фиксированный `<div>` с текстом) и снимать скриншот.
- **Firefox headless запускается только с явным профилем:**

  ```bash
  firefox --headless --profile /tmp/ffprof --window-size 520,600 \
    --screenshot /tmp/out.png http://127.0.0.1:8765/page.html
  ```

- **Проверять надо в том браузере, где заметили проблему.** Фиксированный кегль имени
  в шапке (18px) в Chromium на 390px влезал в строку, а в Firefox на 360px — нет.

## Сравнение макета Claude Design с сайтом

**Главное правило: сравнивать итоговые пиксели рендера, а не исходники.**

Один раз это уже подвело: имя в шапке на макете было розовым, а на телефоне тёмным.
Сверка значений переменных в обоих артбордах показала полное совпадение — и вывод
«всё одинаково» оказался неверным. Расходились не переменные, а то, **какая из них
применяется**.

Причина была в каскаде. В артбордах базовые правила обёрнуты в `.site`, чтобы не текли
наружу, и `.site a` (вес 0-1-1) стало перебивать `.brand` (0-1-0) — имя красилось цветом
ссылок. На сайте то же правило записано как `a{}` (0-0-1) и классу проигрывает.
**Лечится `:where()`**, который веса не добавляет:

```css
:where(.site) a{ color:var(--accent-dk); }
```

Как сравнивать правильно — снять оба рендера и выбрать самый тёмный и самый насыщенный
пиксель в нужной области:

```python
from PIL import Image
px = list(Image.open('shot.png').convert('RGB').crop((20,12,340,40)).getdata())
print(min(px, key=sum))        # цвет текста
```

Прочие отличия макета от сайта, они ожидаемы:

- **Шрифты в артбордах грузятся с Google Fonts**, на сайте лежат локально — песочница
  макета не умеет отдавать свои файлы шрифтов, CSP пускает только `fonts.googleapis.com`.
  Отрисовка чуть отличается, в экспорте PNG/PDF подставится запасная гарнитура.
- **Вместо карты Яндекса — заглушка**, внешние сайты в макет не грузятся.
- **Артборды ничего не делят между собой.** Правку содержимого надо переносить в оба
  руками, иначе десктопный и мобильный разойдутся.
- Мобильный артборд — это **развёрнутые медиазапросы без самих медиазапросов**: правила
  из `@media (max-width:1024px/768px/420px)` вписаны как обычные. Иначе они считались бы
  от ширины окна предпросмотра, а не артборда.

## Вёрстка: замеренные величины

- **Шапке нужно 1010px:** имя с подписью 356px + отступ 24 + меню 581px + поля 48.
  Отсюда порог бургер-меню — `@media (max-width:1024px)`. Если менять текст в шапке
  или пункты меню, **перемерить и поправить порог**, иначе пункты поедут на вторую строку.
- **Кегль имени в шапке — `clamp(13px,4.2vw,25px)`.** Фиксированный ломал ФИО на две
  строки на узких телефонах. На 320px даёт ~13px, на 360 ~15px, на 390 ~16px.
- **Просвет между hero и «Обо мне» задаётся одним правилом** `.hero + .section{ padding-top }`,
  у hero нижнего отступа нет. Так проще крутить: 40px на десктопе, 32px на мобильном.
- **Фото в hero:** 242×325 на десктопе, 150×201 на мобильном — чтобы текст начинался
  примерно с середины экрана телефона.

## Шрифты

Лежат локально в `assets/fonts/`, сайт не ходит на сторонние домены — проверять так:

```bash
grep -oE 'https?://[a-z0-9.-]+' assets/css/style.css index.html | sort -u
# должны быть только krugovova.ru, t.me и yandex.ru (карта)
```

Как забрать шрифт с Google Fonts к себе: запросить CSS **с браузерным User-Agent**
(иначе отдадут ttf вместо woff2), разобрать блоки `@font-face` — перед каждым идёт
комментарий с названием подмножества — и скачать файлы. Нужны подмножества
`cyrillic`, `cyrillic-ext`, `latin`, `latin-ext`. Лицензии OFL берутся из
`github.com/google/fonts/ofl/<имя>/OFL.txt`.

Что всплыло при смене Cormorant Garamond + Manrope на Lora + Golos Text:

- **У Golos Text нет начертания 300**, а базовый вес текста был именно 300 — перевели на 400.
- **У Lora крупнее очко**, в том же кегле она выглядит заметно больше: заголовки секций
  уменьшены с 46 до 40px, имя в hero — отдельно.
- Проверять наличие кириллицы до того, как менять: в CSS от Google Fonts должен быть
  блок с `unicode-range` для cyrillic.

## Картинка превью

`assets/img/og.jpg` собирается из `_og.html` — это страница 1200×630 на стилях самого
сайта, поэтому **после смены палитры или шрифтов её надо пересобрать**, команда в `README.md`.
Снимать надо с запасом по высоте и обрезать: `--window-size=1200,760`, потом `crop((0,0,1200,630))`,
иначе снизу останется белая полоса.
